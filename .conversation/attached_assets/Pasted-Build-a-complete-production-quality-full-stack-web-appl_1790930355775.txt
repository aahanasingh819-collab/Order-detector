# PROJECT PURPOSE

Build an e-commerce order risk detection and investigation platform.

The purpose of the application is to analyze e-commerce orders, detect unusual patterns, assign a risk score, and use AI to explain why an order has been flagged.

The system is a **decision-support tool**.

It must NOT automatically declare an order fraudulent.

The final investigation decision remains with the human reviewer.

---

The complete workflow should be:

Order Data
↓
Anomaly Detection
↓
Risk Signals
↓
Risk Score (0–100)
↓
Risk Level
↓
AI Explanation
↓
Human Investigation

# 3. ANOMALY / RISK ENGINE

Create a lightweight, understandable anomaly detection system.

Do NOT make the system unnecessarily complicated.

The system should analyze available order and customer data and generate risk signals.

Use a transparent scoring approach so that the risk score can be understood and reproduced.

For example, different unusual signals can contribute different amounts to the final score.

The final score must always be between 0 and 100.

Create the anomaly/risk logic in a separate Django service/module rather than putting all the logic inside views.

The system should store the calculated:

* Risk score
* Risk level
* Detected signals

for each order.

The score should be recalculated when appropriate rather than randomly changing.

---

# 4. AI EXPLANATION

Add an AI API integration through Django.

The AI should receive the detected risk signals and relevant order information.

It should generate a concise, human-readable explanation of why the order received its risk score.

For example:

"The order has a significantly higher value than the customer's previous orders. The customer also used a new delivery address and made multiple payment attempts. These signals contributed to the elevated risk score."

The AI explanation should:

* Be easy to understand
* Refer only to detected/evidenced signals
* Not invent facts
* Not automatically call the order fraudulent
* Clearly distinguish observed signals from interpretation where appropriate

Store the generated explanation in the database so that it does not need to be regenerated every time the order page is opened.

Include a button such as:

**Generate / Regenerate Explanation**

Handle API errors gracefully.

If no API key is configured, the rest of the application must still work.

Use environment variables for the AI API key.

NEVER hardcode API keys.
